# الوصول الكامل من البوت — طلب، وقرارك

التجريبي بيوزّع حاله. الوصول الكامل لأ: الطالب بيطلب، وإنت بتوافق أو
بترفض بضغطة من قناة خاصة، وقرارك هو يلي بيعمل الكود.

```
الطالب                        قناتك الخاصة
  │
  ├─ ياخد التجريبي (٢٤ ساعة)
  ├─ يضغط «🔓 بدّي الوصول الكامل»
  ├─ يختار ١ / ٢ / ٣ شهور
  ├─ «طلبك وصل ✅ استنى شوي»  ─────►  🔓 طلب وصول كامل
  │                                    كيكو @kiko · 900123
  │                                    telc · B1 · 3 شهور
  │                                    [✅ وافق]  [✖️ ارفض]
  │                                          │
  │◄──── الكود الكامل 🎉 ──────────────── وافقت
  │◄──── أو سبب الرفض بلغته ───────────── رفضت ← تختار السبب
```

## الحدّ الأمني — وين هو بالضبط

زرّ بتلغرام مو حماية. `callback_data` نصّ عادي بيوصل من أي حساب، ومين
عرف رقم الطلب فيه يبعت `A|<الرقم>` ويوافق على حاله.

**اللي بيمنعه سطر بالقاعدة:**

```sql
if not bot_is_admin(p_admin_telegram_id) then
  raise exception 'not_bot_admin';
end if;
```

`bot_decide_request` بترفض أي رقم تلغرام مو موجود بجدول `bot_admins`.
الزرّ راحة، والقاعدة هي الحارس.

في اختبارين بيثبتوا هاد فعلياً — وحدة بـSQL ووحدة بتشغّل الدالة:
حساب غريب بيضغط «وافق» على طلب حقيقي، والنتيجة `not_bot_admin`، وولا
كود انعمل، والطلب ضلّ معلّق.

## شغلتين تانيتين محميّتين بالبنية

**طلب معلّق واحد لكل حساب** — فهرس فريد جزئي:

```sql
create unique index access_requests_one_pending
  on access_requests (telegram_id) where status = 'pending';
```

ضغطتين متتاليتين ما بيعملوا طلبين، وما بتوصلك نسختين، وما بتوافق
مرّتين. الضغطة التانية بترجّع نفس الطلب.

**الموافقة مرّة وحدة** — `select … for update` بيقفل الصفّ، وبعدها
`status <> 'pending'` بيرجّع «سبق وانبتّ فيه». ضغطتين من أدمنين بنفس
اللحظة بيعملوا كود واحد.

## شكل الكود الكامل

| | التجريبي | الكامل |
|---|---|---|
| المدّة | ٢٤ ساعة | الشهور × ٣٠ يوم |
| النطاق | أوّل امتحان منشور | **كل** امتحانات المستوى |
| الأجهزة | ١ | ٢ |
| التفعيل | مرّة | **٣ مرّات** |
| الملاحظة | `telegram:<id>` | `telegram-full:<id>` |

المستوى هو يلي الطالب اختاره وقت التجريبي.

**مجاني هلق:** ما في دفع بالمسار. الطالب بيطلب وإنت بتوافق. لمّا يجي
وقت الدفع، محلّه بين «اختار الشهور» و«طلبك وصل».

## التركيب

### ١. سرّ جديد

سوپابيس → **Edge Functions → Secrets**:

| Name | Value |
|---|---|
| `ADMIN_CHAT_ID` | وين بدّك الطلبات توصلك |

**الأسهل — رقمك أنت.** ابعت `/id` للبوت، وحطّ الرقم يلي بيرجّعه.
الطلبات بتوصلك رسالة خاصة من البوت. بيشتغل فوراً، بلا ولا إعداد.

**لو بدّك مجموعة بدلها** (مفيدة لمّا يصير في أكتر من شخص بيوافق):
تلغرام بيمنع البوتات من دخول المجموعات افتراضياً، فلازم تفتحها من
**@BotFather → /mybots → بوتك → Bot Settings → Allow Groups? →
Turn groups on**. بعدها ضيف البوت، ابعت أي رسالة، وافتح:

```
https://api.telegram.org/bot<التوكن>/getUpdates
```

دوّر على `"chat":{"id":-1001234567890` — **رقم المجموعة سالب**، خد
الإشارة معه.

> بلا `ADMIN_CHAT_ID` البوت بيضل يشتغل عادي، بس ما بتوصلك إشعارات ولا
> طلبات. الطالب ما إله ذنب إنّك ما ظبّطت السرّ.

### ٢. سجّل مين بيوافق

**الأفضل — سجّل المجموعة، مو الأشخاص.**

لجلب رقم المجموعة: ابعت أي رسالة فيها، وافتح
`https://api.telegram.org/bot<التوكن>/getUpdates`، ودوّر على
`"chat":{"id":-100…` — **الرقم سالب، خد الإشارة معه**. وبالـSQL Editor:

```sql
insert into bot_admins (telegram_id, label)
values (<رقم المجموعة>, 'مجموعة الموافقات')
on conflict (telegram_id) do nothing;
```

**★ العضوية هي الصلاحية.** أي عضو بالمجموعة بيقدر يوافق بلا ما
ينتسجّل لحاله. مين طلع من المجموعة بيفقد الصلاحية فوراً — ما في قايمة
تانية لازم تتزامن بالإيد، ولا حدا بيضل موافق لأنّك نسيت تشيله.

ليش بينفع أماناً: بطاقة الطلب ما بتوصل إلا لمجموعتك، ومين مو فيها ما
بيشوف الزرّ أصلاً. و`cb.message.chat.id` تلغرام بيحطّه مو المستخدم،
فما بينزوّر — والتحويل بيضيّع الأزرار، فما في طريق يوصل الزرّ لبرّا.

**بتقدر تسجّل شخص كمان** (رقم موجب) لو بدّك حدا يوافق من الخاص.
الجدول بيقبل النوعين، والموافقة بتمرق لو **أي** واحد فيهن مسجّل.

**بلا ولا صفّ بهالجدول ما في موافقة** — حتى لو الأزرار بتطلعلك. مقصود.

### ٣. أعد نشر الدالة والسكيما

- الصق `supabase/setup.sql` (صار نسخة **٢٤**)
- أعد نشر دالة `telegram` — نفس طريقة أوّل مرّة

## الحجز — تذكرة لكل طلب

بمجموعة فيها أكتر من شخص، تنين بيفتحوا نفس الطلب وتنين بيردّوا.

فالبطاقة بتوصل **بزرّ واحد بس**:

```
🔓 طلب وصول كامل
كيكو @kiko · 900123
telc · B1 · 3 شهور
          [🖐 احجزه]
```

مين بيضغطه بيصير الطلب إله وحده **١٥ دقيقة**، والبطاقة بتصير:

```
🔓 طلب وصول كامل
كيكو @kiko · 900123
telc · B1 · 3 شهور

🔒 محجوز لـ@houzaifa · 15 دقيقة
غيره لا يضغط.

  [✅ وافق · @houzaifa]  [✖️ ارفض · @houzaifa]
```

★ **اسم الحاجز مكتوب جوّا الأزرار نفسها.** تلغرام ما بيلوّن الأزرار،
وكلّ الأعضاء بيشوفوا نفس البطاقة — فالاسم على الزرّ هو الشي الوحيد يلي
بيوقّف الضغطة الغلط **قبل** ما تصير، مو بعدها.

والمدّة بالدقايق مو بالساعة: البطاقة عليها وقتها من تلغرام، وساعة UTC
بتربك مين ساعته غيرها.

ولو ضغط غيره غلط، بياخد تنبيه: «محجوز لـ@houzaifa — استنى لحتى ينتهي
وقته». والقاعدة هي يلي بترفض، مو الواجهة.

**بعد ١٥ دقيقة بلا قرار:** البوت بيردّ على البطاقة بالمجموعة —
«انتهى وقت الحجز وفلان ما قرّر. الطلب صار حرّ» — والبطاقة بترجع لزرّ
الحجز.

> **ما بيقدر يعمل `@all`.** تلغرام ما بيسمح للبوتات تنادي كل الأعضاء.
> الرسالة بتنزل بالمجموعة فالكل بيشوفها، واللي حجز بينتذكر باسمه.

★ **الحجز بينتهي بالوقت، مو بمهمّة بتمسحه.** `reserve_until` بالماضي
معناها الطلب حرّ — فما في طلب بيضل محجوز للأبد لأنّ التنبيه ما وصل.

### التنبيه بوقته (اختياري)

التنبيه بينبعت مع **أوّل تحديث** بيوصل للبوت بعد انتهاء الحجز. لو
المجموعة والطلاب ساكتين، بيتأخّر.

لو بدّيته بالدقيقة، شغّل هاد **مرّة وحدة** بالـSQL Editor بعد ما
تبدّل السرّ:

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule('bot-sweep', '* * * * *', $$
  select net.http_post(
    url := 'https://ejwzvgabqoevhaimbvik.supabase.co/functions/v1/telegram',
    headers := jsonb_build_object(
      'content-type', 'application/json',
      'x-telegram-bot-api-secret-token', '<سرّ الـwebhook تبعك>'),
    body := '{"cron":"sweep"}'::jsonb);
$$);
```

نفس السرّ يلي بـ`TELEGRAM_WEBHOOK_SECRET` — الدالة بترفض أي نداء
بلاه، فما في نقطة دخول جديدة.

**الشغل بيمشي بلاها**، بس التنبيه بيصير «أوّل ما يتحرّك شي» بدل
«بالدقيقة».

## أسباب الرفض

أربعة جاهزين، بتختار وحدة والطالب بياخدها **بلغته هو**:

| الزرّ عندك | شو بيوصله |
|---|---|
| مو هلق | «مو متاح هلق — جرّب بعد فترة.» |
| جرّب التجريبي | «استفد من نسختك التجريبية أوّلاً.» |
| احكي معنا | «احكي معنا مباشرةً منشان نرتّبلك ياه.» |
| مرفوض | «الطلب مرفوض.» |

**وفي خامس: «✏️ سبب بخطّ إيدك»** — بتضغطه، البوت بيطلب منك تردّ على
رسالته، وبتكتب اللي بدّك ياه والطالب بياخده متل ما كتبته.

★ بلا جدول «مين عم يكتب لأي طلب»: رقم الطلب مكتوب بنصّ رسالة البوت،
وردّك بيرجّعها جوّا `reply_to_message`. رسالة متروكة ساعتين بتشتغل
متل ما هي.

بعد الرفض الطالب بيقدر يطلب من جديد — الفهرس بيمنع المعلّق بس.

## لغة الردّ

لغة الطالب بتتحدّث مع **كل** خطوة بيختارها، مو وقت التجريبي بس. مين
أخد التجريبي بالعربي وطلب الوصول بالألماني، بياخد الردّ بالألماني.

## الأزرار الثابتة — بلا كتابة أوامر

تحت الشاشة في خمس أزرار بتضل ظاهرة، بتطلع مع أوّل كود وبتضل للأبد:

```
🎁 نسختي التجريبية   🔓 وصول كامل
        🎟 كودي
🌐 اللغة             📣 شارك البوت
```

**🎟 كودي** بيرجّع كل أكواده — التجريبي والكامل — مع المستوى والامتحان
وكم باقي لكل واحد. الطالب بيضيّع الرسالة وبيسألك؛ هالزرّ أرخص من
رسالة إلك.

ولزرّ ☰ جنب خانة الكتابة في قائمة أوامر (`/start`، `/sprache`، `/id`)
بشرح بلغة الطالب. بتتظبّط لحالها، ما بدها ولا إعداد.

**★ ليش ما في جدول جلسات؟** ضغطة زرّ بتوصل كنصّ عادي، ونصّ الزرّ لحاله
بيقول الفعل **واللغة** سوا: «🌐 اللغة» عربي و«🌐 Sprache» ألماني. فما
منحتاج نحفظ لغة حدا بين الرسايل — نفس مبدأ `callback_data` يلي حامل
حاله. محادثة متروكة من يومين بتشتغل متل ما هي.

## التجريبي: واحد لكل مستوى

مين جرّب B1 بيقدر يجرّب B2 كمان. قبل كان بياخد «أخدت نسختك من قبل»
ومعه كود B1 — وهو ما شاف B2 بحياته، وهاد بيقفل باب مبيعات مفتوح.

**والرجعة لنفس المستوى لسا بتعطي نفس الكود** مو كود جديد.

★ الحدّ ضلّ مكانه: كل كود ٢٤ ساعة، امتحان واحد، تفعيل واحد، ومستواه
هو. يعني مين بدّه يجمّع أكواد ما ربح ولا امتحان زيادة عن يلي بدّه
يجرّبه فعلاً.

## الرمز: زرّ نسخ بضغطة

```
الرمز:
▌ B14827519366          ← كتلة مميّزة
الرابط: https://…

     [📋 انسخ الرمز]
```

★ **تلغرام ما بيسمح بألوان مخصّصة** برسائل البوتات — ما في طريقة نلوّن
نصّ بلون منختاره. بس `<blockquote>` بيرسم شريط جانبي ملوّن من ثيمة
المستخدم، و`<code>` بيطلع بخطّ وخلفية مختلفين. فالرمز بينفرز عن باقي
النصّ بلا ما نخترع لون — وبيضل مضبوط بالثيمة الفاتحة والغامقة سوا.

★ وزرّ `copy_text` (Bot API 8.0) بينسخ **بضغطة وحدة** — بلا «مطوّل
واختار نسخ»، يلي بيضيّع نصّ الناس على الموبايل.

**ورسالتين مو وحدة:** رسالة وحدة ما بتحمل نوعين `reply_markup`، فرسالة
الرمز بتحمل زرّ النسخ، ورسالة «كيف تستعمله» بتحمل اللوحة الثابتة.
التنتين قصار وإلهن معنى — مو رسالة فاضية لتحمل أزرار.

## «جرّب مستوى تاني»

بعد ما ياخد كوده، بيطلعله زرّ بالمستويات يلي **ما جرّبها بعد** (ويلي
جرّبها ما بتطلع). صار ممكن بعد ترحيل 0028، والطالب ما بيعرف إنّه
بيقدر أصلاً.

## تنبيه «باقي أقلّ من ساعة»

قبل ما يخلص تجريبيّه بساعة، بتوصله رسالة ومعها زرّ **🔓 وصول كامل**.
أقوى لحظة بيع بالرحلة كلها: لسا بالنصّ، وعارف شو عم ياخد، وحاسس
بالوقت عم يخلص.

★ **لمين فعّل كوده بس.** الكود يلي ما انفعّل أبداً ما إله وقت ينتهي،
وتنبيه «باقي ساعة» لواحد ما فتح التطبيق بيربكه مو بيساعده.

★ **ومرّة وحدة لكل كود** (`warned_at` بنفس استعلام الكنس مع
`skip locked`). بينندى من نفس مكان كنس الحجوزات — أي تحديث بيوصل
للبوت، وpg_cron لو ظبّطتها.

## زرّ المشاركة — مو تلغرام بس

ضغطة **«📣 شارك البوت»** بتبعت رسالة فيها تلات طرق:

| | |
|---|---|
| **📲 تلغرام** | `t.me/share` — بيفتح تلغرام |
| **💬 واتساب** | `wa.me` — بيفتح واتساب والنصّ جاهز |
| **الرابط بـ`<code>`** | ضغطة عليه بتنسخه — لإنستغرام أو أي مطرح |

★ ولو `getMe` فشل وما عرفنا اسم البوت، بينبعت النصّ لحاله بلا رابط:
رابط `https://t.me/` فاضي أسوأ من بلا رابط.

اسم البوت بيجي من `getMe` مرّة وحدة بكل تشغيل بارد، مو من سرّ — فلو
بدّلت البوت ما في شي تحدّثه.

## إشعار التسجيل

كل ما حدا ياخد تجريبي **لأوّل مرّة** بتوصلك رسالة بقناتك: مين، أي
مستوى، أي امتحان. الرجعات ما بتنبّهك — وإلا كل من فتح رسالة قديمة
بيرنّ عندك.

## شاشة وحدة بتمشي مع الطالب

القاعدة المتعارف عليها ببوتات تلغرام: **التنقّل بيعدّل الرسالة،
والأحداث بتبعت رسالة جديدة.** ([GramIO — UX Patterns](https://gramio.dev/guides/ux-patterns))

قبل هيك كل ضغطة كانت تزيد رسالة: اللغة، المؤسسة، الدرجة، الكود، كيف
تستعمله… عمود قوايم ميتة، والطالب بيضيع بينهن وممكن يرجع يضغط زرّ قديم
فوق. هلق رسالة وحدة بتتبدّل محتواها مع كل خطوة (`screen()` بـ
`supabase/functions/telegram/index.ts`).

شو بيضل يبعت رسالة جديدة، عن قصد:

| | ليش |
|---|---|
| «كيف تستعمله» بعد الكود | `editMessageText` **ما بيحمل لوحة تحت الشاشة** — بس أزرار جوّا الرسالة. واللوحة الثابتة لازم رسالة. |
| بطاقة الطلب للمجموعة | حدث، وبتضل بالسجلّ |
| «كودي» والمشاركة | جايين من زرّ اللوحة الثابتة — ما في رسالة تنعدّل أصلاً |

تلات حالات معالَجة بـ`screen()`:

- **`message is not modified`** — نفس النصّ ونفس الأزرار. مو خطأ: الشاشة
  أصلاً صحيحة، فمنسكت. ([Telegram Bot API](https://core.telegram.org/bots/api#editmessagetext))
- **رسالة ما عاد فيها تعديل** (انمسحت أو قديمة كتير) — منبعت وحدة جديدة
  بدل ما تختفي الشاشة.
- **ضغطة قديمة** — تلغرام بيرفض الردّ على ضغطة عمرها أكتر من نصف دقيقة.
  ولو رمينا استثناء، الـwebhook بيرجّع 500 و**تلغرام بيعيد نفس الضغطة
  بلا نهاية وبيحبس كل الضغطات الجديدة وراها**. فـ`tgJson()` ما بترمي
  أبداً — الفشل خبر مو انهيار.

## مهلة الخمول: خمس دقايق

الأزرار بتضل بالمحادثة للأبد. مين فتح البوت الصبح وضغط زرّ بعد ساعتين
كان بيكمّل من نصّ طريق نسيه.

`IDLE_SEC = 300` — أي ضغطة على شاشة آخر رسم إلها صار من أكتر من خمس
دقايق بترجّع الطالب لاختيار اللغة، مع تنبيه بيشرح ليش **بلغة الزرّ**.

★ **بلا ذاكرة مؤقّتة ولا جدول جلسات.** الوقت جاي مع التحديث نفسه:
`message.date` وقت الرسالة، و`message.edit_date` وقت آخر تعديل. وبما إنّ
كل خطوة صارت تعدّل نفس الرسالة، `edit_date` هو «إمتى آخر مرّة رسم البوت
شاشة لهالشخص» — يعني آخر تفاعل بالضبط. نفس مبدأ `callback_data` يلي
حامل سياقه.

**أزرارك إنت مستثناة** (`A R X W V`): بطاقة الطلب ممكن تقعد ساعات وبتضل
شغّالة، والحجز عنده مؤقّته هو (١٥ دقيقة).
