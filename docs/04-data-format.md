# Data format

The JSON in `data/` is the contract between `tools/build.py` and `assets/app.js`.
If you ever replace the PDF pipeline — or write new content by hand, or move to
a database — this is the shape you must produce.

## `data/index.json`

```json
{
  "modelle": [
    { "id": "modell-01", "file": "modell-01.json",
      "title": "PETRA", "sections": 9, "aufgaben": 61, "minutes": 150 }
  ]
}
```

`title` is the name stamped on the writing page of each test in the PDF. It is
hard-coded in `build.py` (`NAMES`) because the stamp is an image, not text.

## `data/modell-NN.json`

```json
{
  "id": "modell-01",
  "title": "PETRA",
  "subtitle": "61 Aufgaben · 150 Minuten",
  "blocks":   [ … ],
  "sections": [ … ]
}
```

### `blocks` — what the student starts

A block is one sitting of the real exam. Always three, in this order:

```json
{ "id": "block-lv-sb",
  "title": "Leseverstehen und Sprachbausteine",
  "minutes": 90,
  "hint": "Aufgaben 1–40",
  "parts": ["lv1", "lv2", "lv3", "sb1", "sb2"],
  "maxPoints": 105.0,
  "availablePoints": 105.0,
  "missing": 0 }
```

| Field | Meaning |
|---|---|
| `parts` | section ids that make up this block, rendered one after another |
| `minutes` | the official time for the whole block — **not** the sum of its sections' `minutes` |
| `maxPoints` | the official telc maximum. Always 105 / 75 / 45 |
| `availablePoints` | what is actually reachable given the questions that survived extraction |
| `missing` | how many official questions are absent |

`maxPoints` vs `availablePoints` is the mechanism that keeps incomplete tests
comparable — see [07-scoring.md](07-scoring.md).

### `sections` — the content

```json
{ "id": "lv1",
  "group": "Leseverstehen",
  "title": "Leseverstehen, Teil 1",
  "minutes": 15,
  "instruction": "Lesen Sie die Überschriften a–j …",
  "format": "matching",
  "bankTitle": "Überschriften",
  "bank": [ { "key": "A", "text": "Angebot für Reisende: …" } ],
  "pointsPerItem": 5.0,
  "maxPoints": 25.0,
  "availablePoints": 25.0,
  "missing": 0,
  "items": [ … ] }
```

There are always the same nine section ids when a test is complete:
`lv1 lv2 lv3 sb1 sb2 hv1 hv2 hv3 sa`.

## The five formats

`format` decides how the section renders and how it is scored.

### `matching` — text ↔ heading, or situation ↔ ad
Used by `lv1` and `lv3`. Needs `bank`. Renders a `<select>` per item.
Each bank key can be used only once (`X` in `lv3` is exempt — it means
"no matching ad").

```json
"items": [ { "id": "1", "text": "Ich möchte, dass Menschen …", "answer": "B" } ]
```

`lv3` additionally carries `bankImage`, because the ads are a picture in the
source PDF, not text:

```json
"bankImage": "img/m01-lv3.jpg"
```

The path is relative to `data/`. In the single-file bundle it is replaced by a
`data:` URI, and `renderBank()` checks for that prefix.

### `mc` — multiple choice A/B/C
Used by `lv2` and `sb1`. Options live on the **item**, not the section:

```json
{ "id": "6",
  "text": "Die Werbung in den Vereinigten Staaten",
  "options": [ { "key": "A", "text": "beschäftigt sich überhaupt nicht mit Deutschland." },
               { "key": "B", "text": "zeigt immer wieder dasselbe Bild von Deutschland." },
               { "key": "C", "text": "zeigt viele unterschiedliche Seiten von Deutschland." } ],
  "answer": "B" }
```

For `sb1` the `text` is not a question but a snippet of context around the gap,
generated by `gap_context()`: `"… ich mich sehr über Ihren (26) freuen würde …"`.

### `wordbank` — fill gaps from a word list
Used by `sb2`. Needs `bank` (keys `a`–`o`, uppercase words). Items are generated
from the number range 31–40 rather than parsed, because the gaps are numbered
inline in the letter text.

These are the only items that get an explanation, and it is mechanical:

```json
{ "id": "31", "text": "… bin ich (31) Ihrer Anzeige …",
  "answer": "D", "explain": "Das Wort lautet: AUF" }
```

### `truefalse` — Richtig / Falsch
Used by `hv1`–`hv3`. No options, no bank. `answer` is `"r"` or `"f"`
(normalised from `+`/`-` in the PDF answer key).

Every listening section also carries a `note`, which the app shows as a warning
before the block starts:

```json
"note": "Hinweis: Die Hörtexte sind in der PDF-Vorlage nicht enthalten. …"
```

### `writing` — the letter
Used by `sa`. The only section with one item and no `answer`.

```json
{ "format": "writing",
  "brief": { "intro": "…", "greeting": "Liebe Petra,",
             "paragraphs": ["…", "…"], "signature": "Deine Anna" },
  "instruction": "Antworten Sie auf den Brief. …",
  "hints": ["Schreiben Sie mindestens 100 Wörter."],
  "criteria": [ { "title": "Aufgabenbewältigung", "hint": "Sind alle vier Leitpunkte …?" },
                { "title": "Kommunikative Gestaltung", "hint": "…" },
                { "title": "Formale Richtigkeit", "hint": "…" } ],
  "grades":  [ { "key": "A", "points": 5 }, { "key": "B", "points": 3 },
               { "key": "C", "points": 1 }, { "key": "D", "points": 0 } ],
  "factor": 3,
  "maxPoints": 45,
  "items": [ { "id": "A", "text": "Antworten Sie auf den Brief …",
               "minWords": 100,
               "points": ["Warum Sie gern nach Deutschland kommen möchten",
                          "Wie Sie anreisen wollen", "…"] } ] }
```

`brief` is the letter the student must answer; `items[0].points` are the four
content bullets they must cover. Grading is by self-assessment:
`(sum of three criteria) × factor` = up to `(5+5+5) × 3` = 45.

## Shared item fields

| Field | Type | Present |
|---|---|---|
| `id` | string | always — the official question number ("1"…"60"), or `"A"` for writing |
| `text` | string | always |
| `answer` | string | all formats except `writing` |
| `options` | array | `mc` only |
| `explain` | string | optional — currently only `wordbank` (160 of 912 items) |
| `num` | string | drill runs only — the original number, since `id` is rewritten |
| `minWords`, `points` | | `writing` only |

## `passages` — the reading text

Sections `lv2`, `sb1`, `sb2` carry the text the questions refer to:

```json
"passages": [ { "paragraphs": [ { "t": "Leipzigerin geht in den USA auf Sendung", "b": true },
                                { "t": "Manchmal fühle ich mich wie ein Missionar …", "b": false } ] } ]
```

`b: true` marks a heading. The PDF's fonts are obfuscated (`font2`, `font4`), so
bold cannot be detected by name — `sections.py` infers headings from font size
relative to the page median. See [05-build-pipeline.md](05-build-pipeline.md).

## Invariants

Verified across all 16 files; keep them true if you generate data another way:

1. Every non-`writing` item has an `answer`.
2. For `mc`, `answer` is one of that item's `options[].key`.
3. For `matching`/`wordbank`, `answer` is one of the section's `bank[].key`.
4. For `truefalse`, `answer` is `"r"` or `"f"`.
5. Item ids are unique within a section.
6. A block's `availablePoints` equals the sum of its parts' `availablePoints`.
7. `maxPoints` is always 105 / 75 / 45 per block, 225 per test.
8. Items with no reliable answer are **dropped at build time**, never shipped
   with a guess. That is why `missing` exists.

A question whose answer could not be matched to the key is deleted rather than
guessed — a deliberate choice that trades coverage for trustworthiness.
